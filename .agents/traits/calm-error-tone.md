---
name: calm-error-tone
subject: Wording of error messages.
requirement: Error messages use calm, direct, ordinary language that describes
  the problem without blaming the caller or a third party. Public messages use
  the product's domain vocabulary; internal messages may name the failing
  internal capability when that helps an operator.
applicability: Public messages exclude database tables, framework or runtime
  mechanics, stack traces, vendor exceptions, and internal service names.
purpose: Keeps failures serious and understandable for the audience reading them.
---
Leave out jokes, cutesy language, excessive apologies, and alarmist wording.
